# Developing the typst template

The maintainers' side of the typst template; its users' documentation is
[docs/typst.md](../../docs/typst.md). The template is [typst/](../../typst): a template root, every
file a generated project gets, with Liquid in it. What checks it is here and in the repository's
tooling:

```text
dev/typst/render-check.py           every templated file rendered and checked (below)
dev/typst/answers.toml, smoke.sh    `just generate typst` and `just smoke typst`
dev/typst/lock.py, lock.files       `just lock-update typst`, and what it may change
.github/workflows/smoke-typst.yml   the end-to-end check, which smoke.yml runs
docs/typst.md                       the users' documentation
```

The rest -- the root justfile and flake, the shared files, the workflows that check every template
-- is the repository's, one set for every template ([CONTRIBUTING.md](../../CONTRIBUTING.md),
[AGENTS.md](../../AGENTS.md)). Run from the root:

```sh
nix develop                     # the root's shell: cargo-generate, just, the linters, Python
just render-check typst         # the checks below; with no template named, every template's
just smoke typst package        # generated by cargo-generate, then its own checks (and `template`)
just generate typst template    # into target/typst/template/demo, to look at
just lock-update typst          # the lock moved, every tool with it (locks.yml's)
just checks                     # every template's render-check, sync, no tool version by hand,
                                # the shell, the workflows, dprint, cog, the flake's last
just format                     # every formatter the checks hold the files to, `nix fmt` last
```

`just smoke typst <kind>` runs the generated project's checks in its own flake's shell, then `just
format`, which must change nothing, as the smoke test's Nix job does (`dev/typst/smoke.sh`, both's);
its tools are at the root's versions, as the root's flake.lock is typst's. It needs Nix, and its
first run compiles typst-package-check, which nixpkgs does not carry.

`just checks` at the root runs every template's render-check with the repository's own checks:
[CONTRIBUTING.md](../../CONTRIBUTING.md#development-workflow) lists them.

## render-check

`just render-check typst` installs `dev/requirements.txt` into `.venv` (Python 3.11+, for tomllib)
and runs `dev/typst/render-check.py`, which renders every templated file for 32 combinations of
`project_kind` × `license` × categories (a package's none or two, a template's one or three) ×
email, keywords and disciplines (empty or present), then checks that nothing is left unexpanded and
that the result parses as TOML, YAML, JSON and -- with `nix-instantiate` on `PATH` -- Nix. It also
guards what fails silently otherwise:

- **Every referenced variable is declared.** cargo-generate renders an unknown variable as an
  empty string, and a file it cannot render at all as it stands, without a word -- no "leftover
  `{{`" check sees either.
- **No file on the `exclude` list contains a placeholder, and every binary file is on it**: those
  are copied verbatim -- the workflows (GitHub's `${{ }}`), the justfile (just's `{{ }}`),
  cliff.toml (Tera, which Liquid would evaluate silently), the Typst code, the flake -- and a binary
  one (the tests' references) cargo-generate refuses to render and aborts on.
- **The regexes are Universe's.** Each default passes its own; every category and discipline
  passes, alone and listed together, and an unknown one, a fourth category, a template without
  one and a GitHub handle with `--` do not; with `nix` on `PATH` (CI's), the `compiler` regex takes
  0.12 to the lock's Typst (nixpkgs', at `typst/flake.lock`) and nothing newer.
- **Every `ignore` and `export-ignore` path exists**, and none of the latter is the package's own.
- **The licence texts agree**: `LICENSE`'s branch for each licence is byte for byte the file it
  also is.
- **Each `typst.toml` describes its case**: the licence expression, `authors`, `[template]`
  exactly for a template package, the lists, the entrypoint's module; and each case keeps exactly
  the licence files its `license` and README name.

The checks every template shares are [dev/render_core.py](../render_core.py)'s -- each prompt's name
(none cargo-generate reserves) and default (against its choices and its regex), the generation
answers (`answers.toml`) against the prompts, the `ignore` paths and the hooks, the variables and
the encoding, the exclude list, every case rendered and parsed -- and `dev/typst/render-check.py`
adds typst's own on top. Each check runs on its own: one that fails, or cannot run because a file
before it did not render, is reported, the rest still run, and the exit status is 1.

## The shared files

What typst shares with the other templates or the root is `just sync --check`'s: the files
[shared/manifest.toml](../../shared/manifest.toml) names, each copy byte for byte its original and
executable alike, and dprint's plugins and TOML settings, every template's. Change the original,
then `just sync`; the lock, `just lock-update typst` ([dev/typst/lock.py](lock.py): every tool
follows it, a project's CI building its flake's `tools`), or by hand `nix flake update` in `typst/`
or at the root, then `just flake-sync`.

## CI

- `checks.yml`, on every pull request, every push to `main`, weekly and by hand: `just sync
  --check`, `just tool-versions-check` and every render-check.
- `smoke.yml`: `smoke-typst.yml` when a run needs it -- a pull request touching `typst/`,
  `dev/typst/` or the workflow itself, or anything but another template's own files and `docs/`;
  every push to `main`, weekly and by hand -- behind one gate, `smoke-gate`. It generates every kind
  × licence × email answer through the real cargo-generate (typst.toml, the licence files, dprint),
  and refuses what Universe would: two names, a description with "Typst", a GitHub handle past 39
  characters, a template without a category; for each kind, with the tools its own CI installs
  (`.github/install-tools.sh`: the flake's, at its lock), the hooks refusing what CI would, `just
  checks` but the flake's, a planted lint refused, `just floor`, two releases against a bare remote,
  each tag then read and bundled as `publish.yml` does, and the bundle accepted by typst/packages'
  own bundler; for each kind under Nix, generated by the lock's cargo-generate (the other jobs by
  the floor, 0.25.0), the flake's checks and `just checks` in its dev shell, then `just format`
  changing nothing.
- `nix.yml`: the root flake (`just nix`): its format, the shell (every template's) and the
  workflows (every template's).
- `style-check-dprint.yml`, `style-check-cocogitto.yml`: dprint and the commits.
- `dependabot-automerge.yml`: Dependabot's patch and minor bumps (the actions, render-check's
  packages) merged once the required checks pass.
- `locks.yml`, monthly and by hand: `just lock-update typst` -- the lock, the root's and
  `shared/`'s with it, every tool with them -- proposed as a pull request on `locks/typst`, whose
  description names each tool that moved and what is left to a person.
- `dprint-plugins.yml`, monthly and by hand: `just dprint-update` -- every `dprint.json`'s plugins,
  this template's with them, to their newest, the root formatted by them -- proposed as a pull
  request on `dprint/plugins`.
- `release.yml`: a release tag's GitHub release, every template's at once (`just release` cuts it:
  the changelog, the tag `v<version>`), with every tracked file as a tarball: GitHub's own source
  archives are `git archive`'s, so they lack what `typst/.gitattributes` export-ignores.

## Verification status

### In this repository

`typst/` was typst-template's `template/` at its last published commit, `ad92437`, when it moved
here; once the move was complete, every project generated from it was byte for byte -- contents and
modes -- that commit's, but for one comment block in `.github/workflows/dependabot-automerge.yml`,
made exact here. That was proved by generating every kind × option the smoke test covers (18
projects, and the 5 answers it refuses) from both repositories, by `--path` and by `--git` from a
branch and from a tag; what changed since is this repository's history. Also run here:

- **render-check** passes, and still catches each defect planted in it: a misspelled variable, a
  glob in `ignore`, a regex refusing its default, Liquid in an excluded file, a file that is not
  UTF-8, invalid YAML, broken Liquid, an answer in `answers.toml` no prompt takes or one its prompt
  refuses. The shared files' drift is `just sync --check`'s, which fails on each copy changed (a
  byte appended or changed in place), its executable bit flipped or the copy missing, any line of
  the three shared recipes changed, a dprint plugin apart, and Liquid in a `[root]` original where
  cargo-generate itself renders it.
- **smoke-typst.yml's steps**: the combinations and the refused answers, each kind's generation, and
  the Nix jobs' generation by the lock's cargo-generate (nixpkgs' 0.25.0, without its `git`
  feature), each project equal to the released binary's; `dev/install-cargo-generate.sh` installs
  the floor's, its archive checked against its pinned SHA-256. Every generation runs with no network
  (`dev/offline.sh`), proved as the runner's user, through sudo, by both builds of cargo-generate:
  each project the same as with it.
- **CI's installer**, a generated project's `.github/install-tools.sh`, with `nix` and `docker`
  stood in for: it builds the flake's `tools` from the lock as committed (`--no-update-lock-file`),
  pulls the image of the lock's package-check tag (`0.7.0`), and puts their `bin/` and the command
  running that image on `GITHUB_PATH`; a lock whose input has no tag, or one that is no version, is
  refused before anything is built. `tools` evaluates, with the real Nix, to the nine tools at the
  lock's versions; building it, from nixpkgs' binary cache, and the pull are CI's.
- **The root's recipes**: `just smoke typst package` and `just smoke typst template` pass (typst
  0.15.1, tytanic 0.4.1, typstyle 0.15.1, tinymist 0.15.8, typst-package-check 0.7.0), in the
  generated flake's dev shell as a stand-in `nix` has it: its own packages at their versions, and
  nothing else (but git, awk, Python's patch release and stdenv's other tools, this machine's);
  every kind `just generate typst` makes equals what smoke-typst.yml's generate and Nix jobs make.
- **The flake**, every kind's, on its own lock: it evaluates on every system, and its `format`,
  `shell` and `workflows` checks pass as their derivations run them, git and awk aside; the
  Nix job's steps after generation pass in its dev shell, as above (awk aside; `nix fmt` and `nix
  flake check` left to CI).
- **[New Typst releases, and the floor](../../docs/typst.md#new-typst-releases-and-the-floor)**,
  as written: render-check's `compiler` cap failing a regex short of the flake's Typst ("refuses
  the flake's Typst, 0.15.1") and one past it ("accepts 0.15.2"); the floor as `typst.toml`'s
  `compiler` alone, which CI's second job and `just floor` read; the references' paths. Not run: a
  Typst newer than the lock's, and so a reference re-rendered.

### In typst-template, before the move

The template was driven end to end with the real tools, not reasoned about. With **cargo-generate
0.25.0**, **typst 0.15.1**, **tytanic 0.4.1**, **typstyle 0.15.1**, **tinymist 0.15.8**,
**typst-package-check 0.7.0** (built from its tag), **just 1.58.0**, **shellcheck 0.11.0**, **shfmt
3.14.1**, **actionlint 1.7.12**, **cocogitto 7.0.0**, **git-cliff 2.14.2** and **dprint 0.61.1**
(markdown 0.26.0, TOML 0.9.0), all 16 kind × licence × email combinations generate and, after their
first commit, pass `just --fmt --check` and `just checks` but for `nix`: `tools-check`,
`format-check`, `lint`, `shell-check`, `actionlint`, `test`, `versions-check`, `readme-check`,
`template-check`, `package-check`, `dprint-check` and `cog`.

Also confirmed by running it:

- **The floor**: the README and the template compile on Typst 0.12.0 and 0.14.0 (`just floor`,
  with `compiler` set to each).
- **The bundle**: exactly the package's files (typst.toml, src/, template/, README.md, the
  licences, after a release the changelog); a template's thumbnail 2067 × 2923 px, about 650 KB, of
  the template as `typst init` made it; package-check silent on it offline, and failing on a staged
  file it warns of (`exclude/example`) and, online, on a repository that does not answer. A
  committed `scripts/dev.sh` and `docs/manual.pdf` stop `just bundle`, naming each; listed in
  `exclude`, the manual passes, and export-ignored, the script.
- **The checks fail when they should**: a README block with a warning (an unknown font) or with no
  language -- fenced with backticks or tildes, indented in a list or not -- an import of a stale
  version, unformatted Typst code; `just lint`, in both kinds, on a set rule that takes no effect
  in a module the entrypoint imports, a show rule that takes none in a template package's
  template, and a compiler warning (an unknown font family), on which `tinymist lint` itself exits
  0. Only a diagnostic counts, not a dependency's download progress on Typst's stderr.
- **Releases** against a bare remote, through the git hooks: a package's first release tags
  `v0.1.0` (the declared version, whatever the level) and writes the changelog; a second, after a
  `fix!`, bumps to `v0.2.0` -- `typst.toml` and the README's import -- the breaking change first and
  a compare link; a template package's moves `template/main.typ`'s import too, and its template
  still compiles; an empty release, an unpushed `main`, a dirty tree and an unknown level are
  refused; a planted stale import makes the release refuse and put every file back. Each tag, at
  its own commit, passes publish.yml's steps: its version, its notes, its bundle linted.
- **typst/packages' own bundler** (its deploy's, built from its main) accepts all 16 bundles --
  their SPDX expressions, `authors`, categories, entrypoints and thumbnails -- and a template whose
  page is a business card's, its thumbnail re-rendered to 1081 px. package-check, in its
  typst/packages mode (`check @preview/<name>:<version>` in a clone, the submission committed as
  publish.yml commits it), is silent too.
- **The smoke test's own steps**, run locally as written (installs aside) for both kinds: generate,
  the hooks, `just checks` but `nix`, the planted lint refused, `just floor` on Typst 0.14.0, the
  releases and each tag's bundle, and the bundler's acceptance. publish.yml's push to a fork, run
  against a local bare repository standing in for it: the branch, the commit's author and message,
  the link; and, the fork synced and then checked out itself, the push sends the package alone (7
  objects over a 200-commit history, with `push.negotiate` off and typst/packages moved before the
  sync).
- **`just install`**: the bundle as `@local/<name>:<version>`, which a document then imports; for
  a template package, `just install preview`, which `typst init` then starts a project from that
  compiles (its `main.typ` imports `@preview/`).
- **The git hooks**: unformatted Typst code, a stale import, a message cog rejects and a pushed
  revert refused; a clean push accepted.
- **The flakes** of both kinds -- and typst-template's own, whose lock was the template's, as the
  root's is here -- evaluate on all three systems (`nix flake check --no-build --all-systems`, Nix
  2.34.6, the shipped flake.lock) and are nixfmt 1.5.0-clean. The `pins` check reports nothing for
  the shipped pins, and names a mutated pin and an unknown one; it and `just tools-check` each name
  a wrong tinymist or actionlint pin. Run as their derivations run them -- the files copied out, no
  network, no `/usr/bin/env` (the Linux sandbox has none, and just runs a script recipe through its
  shebang) -- the `tests`, `format`, `shell`, `workflows` and `lint` checks pass for both kinds;
  `shell` fails without the shebang rewritten, and `lint` on the planted set rule.
- **`nix fmt` and `just format`**: each flake's formatter, `nix fmt -- --ci` run as treefmt 2.6.0
  with its settings, passes on typst-template and on both kinds generated, and fails on a planted
  change, a misindented recipe line in either justfile there or in a generated project's among them.
  `just format`, `nix fmt` so emulated, changes nothing on what generation wrote and puts back each
  planted drift: in a template package, Typst code, a shell script, a justfile recipe line, a script
  recipe shfmt would reformat (`just shell-check`'s verdict), Markdown, the Nix; in typst-template,
  a shell script, a recipe line in either justfile, Markdown.
- **render-check** caught each of eleven planted defects -- a misspelled variable, a glob in

  `export-ignore`, a `compiler` regex past the pins, a binary file not excluded, a wrong licence
  file kept, an SPDX expression without its parentheses, a fourth category -- and each planted
  drift of its copies, the guard `just sync --check` now is.
- **The shell**: `just shell-check` passes in typst-template's root, in `template/` and in both
  kinds generated; at that root it fails on a planted unquoted variable (SC2086), a script recipe
  with a `{{ }}` interpolation, a recipe line indented off its style and an unformatted script; in a

- **The workflows** -- typst-template's and the template's -- pass actionlint 1.7.12 with
  shellcheck 0.11.0. In a generated project, `just actionlint` and the pre-commit hook pass, and the
  hook refuses a workflow with an unquoted variable in a `run:` script.
- **The downloads**, as they were then (since replaced: cargo-generate's floor alone is downloaded

- **typst-template's recipes**: `just smoke package` and `just smoke template` pass. `just
  release`, against a bare remote, through the hooks: `v0.1.0` first, whatever the level, then

### Not covered

What neither covers -- the smoke test on GitHub is what does:

- **Builds under Nix.** The flakes' derivations were evaluated, never built: these environments
  reach no binary cache. So typst-package-check's build from its flake (its `cargoHash` against
  this nixpkgs) and the checks as derivations have not run there.
- **GitHub Actions itself**: setup-typst, setup-tytanic, the package-check image, the GitHub
  releases (`gh release create`) and the push to a typst/packages fork are linted, not run.
