# Developing the python template

The maintainers' side of the python template; its users' documentation is
[docs/python.md](../../docs/python.md). The template is [python/](../../python): a template root,
every file a generated project gets, with Liquid in it. What checks it is here and in the
repository's tooling:

```text
dev/python/render-check.py           every templated file rendered and checked (below)
dev/python/answers.toml, smoke.sh    `just generate python` and `just smoke python`
dev/python/lock.py, lock.files       `just lock-update python`, and what it may change
.github/workflows/smoke-python.yml   the end-to-end check, which smoke.yml runs
docs/python.md                       the users' documentation
```

The rest -- the root justfile and flake, the shared files, the workflows that check every template
-- is the repository's, one set for every template ([CONTRIBUTING.md](../../CONTRIBUTING.md),
[AGENTS.md](../../AGENTS.md)). Run from the root:

```sh
nix develop                     # the root's shell: cargo-generate, just, the linters, Python
just render-check python        # the checks below; with no template named, every template's
just smoke python workspace     # generated by cargo-generate, then its own checks (each kind)
just generate python bin        # into target/python/bin/demo, to look at
just lock-update python         # the lock moved, its pins with it (locks.yml's)
just checks                     # every template's render-check, sync, no tool version by hand,
                                # the shell, the workflows, dprint, cog, the flake's last
just format                     # every formatter the checks hold the files to, `nix fmt` last
```

`just smoke python <kind>` needs Nix: the generated project's lock is written, and its checks run,
in its own flake's dev shell.

`just checks` at the root runs every template's render-check with the repository's own checks:
[CONTRIBUTING.md](../../CONTRIBUTING.md#development-workflow) lists them.

## render-check

`just render-check python` installs `dev/requirements.txt` into `.venv` (Python 3.11+, for tomllib)
and runs `dev/python/render-check.py`, which renders every templated file for all 108 combinations
of `project_kind` (with the image or without; a lib with it unasked, or given anyway) × `license` ×
`python_min` × empty-or-present email and keywords, then checks that nothing is left unexpanded and
that the result parses as TOML, YAML, JSON and -- with `nix-instantiate` on `PATH` -- Nix. It also
guards what fails silently otherwise:

- **Every referenced variable is declared.** cargo-generate renders an unknown variable as an
  empty string, and a file it cannot render at all as it stands, without a word (0.25,
  measured: Liquid's `include` is one such) -- no "leftover `{{`" check sees either.
- **No file on the `exclude` list contains a placeholder**: those are copied verbatim -- the
  workflows (GitHub's `${{ }}`), the justfile (just's `{{ }}`), cliff.toml (Tera, which Liquid
  would evaluate silently), the Nix files and the hooks.
- **Every templated file is UTF-8**: cargo-generate aborts on one that is not, so a binary file
  must be excluded.
- **Every `ignore` entry is a literal path that exists.** `ignore` is not glob-matched, and
  removes paths before rendering, so an entry spells a path as the template does.
- **The copies agree.** Liquid has no includes here, so the workspace members repeat the single
  package's code, manifest table and licence texts; the check holds them equal, but for what
  tells them apart.
- **The manifests describe their layout**: `.python-versions`, `requires-python`, the
  classifiers, ruff's and basedpyright's targets, the licence files, the kind; and the image's
  Nix file, workflow and flake output, all present or all absent.

The checks every template shares are [dev/render_core.py](../render_core.py)'s -- each prompt's name
(none cargo-generate reserves) and default (against its choices and its regex), the generation
answers (`answers.toml`) against the prompts, the `ignore` paths and the hooks, the variables and
the encoding, the exclude list, every case rendered and parsed -- and `dev/python/render-check.py`
adds python's own on top. Each check runs on its own: one that fails, or cannot run because a file
before it did not render, is reported, the rest still run, and the exit status is 1.

## The shared files

What python shares with the other templates or the root is `just sync --check`'s: the files
[shared/manifest.toml](../../shared/manifest.toml) names, each copy byte for byte its original and
executable alike, and dprint's plugins and TOML settings, every template's. Change the original,
then `just sync`. python's `flake.lock` is its own: `just lock-update python`
([dev/python/lock.py](lock.py)) makes it in a generated project, as the template's `flake.nix` holds
Liquid, copies it back, then moves the pins of `pyproject.toml`'s dependency groups and uv's
`required-version` to what each kind's `pins` check reports.

## CI

- `checks.yml`, on every pull request, every push to `main`, weekly and by hand: `just sync
  --check`, `just tool-versions-check` and every render-check.
- `smoke.yml`: `smoke-python.yml` when a run needs it -- a pull request touching `python/`,
  `dev/python/` or the workflow itself, or anything but another template's own files and `docs/`;
  every push to `main`, weekly and by hand -- behind one gate, `smoke-gate`. It generates every kind
  × licence × email answer through the real cargo-generate; manifests, licence
  files, the lock's dprint), and refuses the names that are no Python import name; for each kind,
  generated by the lock's cargo-generate, in the generated flake's dev shell, the lock written, the
  hooks refusing what CI would, `just checks` with the flake's checks built, `just pins-update` and
  `just format` changing nothing, the image run (bin's and workspace's), the changelog and the
  build; and for `bin` and `workspace` (`lib` releases as `bin` does), real releases against a bare
  remote, each tag then read as `publish.yml` reads it.
- `nix.yml`: the root flake (`just nix`): its format, the shell (every template's) and the
  workflows (every template's).
- `style-check-dprint.yml`, `style-check-cocogitto.yml`: dprint and the commits.
- `dependabot-automerge.yml`: Dependabot's patch and minor bumps (the actions, render-check's
  packages) merged once the required checks pass.
- `locks.yml`, monthly and by hand: `just lock-update python` -- the lock and the pins that follow
  it -- proposed as a pull request on `locks/python`, whose description names what is left to a
  person.
- `dprint-plugins.yml`, monthly and by hand: `just dprint-update` -- every `dprint.json`'s plugins,
  this template's with them, to their newest, the root formatted by them -- proposed as a pull
  request on `dprint/plugins`.
- `release.yml`: a release tag's GitHub release, every template's at once (`just release` cuts it:
  the changelog, the tag `v<version>`), with every tracked file as a tarball, which cargo-generate
  generates from, unpacked, with `--path`.

### Not covered

What neither covers -- the smoke test on GitHub is what does:

- **Builds under Nix.** The flakes' derivations were evaluated, never built: these environments
  reach no binary cache. So the flake's tests, types and lint, the command check and the image have
  not run there; the smoke test builds the image, runs it in Docker and reads its user and labels.
- **GitHub Actions itself**, PyPI's Trusted Publishing, the GitHub release and the GHCR push:
  linted, not run.
